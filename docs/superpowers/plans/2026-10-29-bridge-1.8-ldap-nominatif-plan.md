## Goal

Bridge **1.8** : connexions `wyre` **et** `be` en login PG nominatif authentifié par l'AD Constructel en LDAPS (même mot de passe que Windows, zéro mot de passe stocké), sonde unique anti-verrouillage, repli D7 pour wyre, coupure nette pour be, `verify-full` obligatoire, **scopes MRO/POP et capacités lecture/écriture Farois effectifs et visibles dans QGIS**. La **clôture 1.8.x** (suppression du repli wyre, zip sans identifiant) est incluse dans ce chantier, derrière le gate lot 4.

## Success Criteria

- **wyre** : AC8 (sonde unique → repli + bandeau si non activé ; nominatif au redémarrage après activation ; 1 seule ressaisie si mot de passe Windows changé ; ≤ 2 binds refusés ; 0 verrouillage AD), AC7 (`verify-full`, échec sans `root.crt`), AC9 (aucune pose de `app.current_user` en nominatif, statu quo en repli).
- **be** : chaque externe se connecte avec son login AD + mot de passe Windows ; aucun mot de passe PG n'existe ni ne transite ; droits exactement ceux du rôle partagé (USAGE `public` + DML tables `public`, rien d'autre — relevé avant/après identique) ; `bureau_etudes` NOLOGIN ; plus aucune session partagée ; `is_gis_session()` faux pour les logins be ; sortie du groupe AD → `NOLOGIN` + sessions coupées à la prochaine réconciliation.
- **Scopes** : un DESIGNER scopé M1 ne voit que ses objets (couches réseau + `v_duct_progress`) et écrit dans son périmètre ; un rôle sans `network.write` a ses couches wyre.* en lecture seule dans QGIS avec message explicite ; un ADMIN voit tout ; couches vides hors périmètre = comportement documenté, pas un ticket.
- **Clôture** : zip 1.8.x sans `wyre.password`/`wyre.user`, repli supprimé, bandeau devenu erreur bloquante (AC12 complet).
- **Publication 1.8** : serveur wyre (lots O4) + serveur be déployés et vérifiés, tous les logins (wyre pilotes + be) créés et testés, GO explicite de Simon.
- Tests : pytest 163 passés conservés, 9 échecs mTLS connus inchangés, nouveaux tests verts.

## Approach

Volet serveur Farois (migration N+1) + volets plugin, même chantier. `bureau_etudes` devient un **rôle groupe NOLOGIN** (grants mig 335 inchangés, pattern `ftth_editor`, jamais de `PASSWORD`) ; rôles LOGIN nominatifs `IN ROLE` créés par admin ; authentification par les lignes `ldap` (même serveur/suffixe que wyre), restreintes à `+bureau_etudes`. L'exclusion GIS de 083 (nom exact `bureau_etudes`, l.86/134) est étendue au **groupe** par un test sûr (faux pour `postgres`/`ftth_admin` en premier). Pas de `ref.users` pour les externes, donc pas d'activation via l'UI : création manuelle par admin (faible volume) + réconciliation automatique qui passe `NOLOGIN` les rôles sortis du groupe AD BE (jamais de création auto en `LOGIN`). La migration ne coupe jamais : `NOLOGIN` = geste ops séparé à la publication.

Côté plugin, logique pure testable sans QGIS (`bridge_nominatif.py`, pattern Bridge 0), partagée par les deux connexions. wyre : Auth Manager Basic `9i19s56` avec `username=<login>`, sonde psycopg2 + lecture SQLSTATE classe `28`, 1 ressaisie, repli D7 mémorisé en settings. be : Auth Manager `07254s7` nominative, même sonde (1 ressaisie, anti-verrouillage AD identique), pas de repli (coupure nette). `root.crt` commun par upsert de blocs PEM (CA Farois + racine AD, calqué sur `upsert_pgpass_entry`), `verify-full` (`"5"`) sur les deux connexions, échec bloquant si `root.crt` non écrit.

Scopes : le serveur filtre déjà (RLS 502 dès J1, `v_duct_progress` et `v_element_documents_list` en `security_invoker` — vérifié) ; le plugin **lit** les capacités/périmètres de session (`ref.role_capabilities`, `ref.user_data_scopes`, SELECT conservé aux nominatifs par F19 — vérifié) et les **rend visibles** : couches en lecture seule sans `network.write`, périmètre affiché, couches système vérifiées (`v_form_lists` sans invoker mais sans portée MRO/POP — vérifié sans impact).

## Steps

### Volet A — serveur be nominatif LDAPS (Farois)

- **A1. Migration N+1 (+ rollback `N+1r`)** : étend l'exclusion 083 de `bureau_etudes` exact au groupe (test sûr documenté) ; vérifications (083 présent, pas de capture `ftth_admin`/`postgres`) ; registre `esb.applied_migrations` ; ne touche ni aux grants ni à `LOGIN`. Patron : migrations 502/505 (en-tête, `ON_ERROR_STOP`, `BEGIN`, `lock_timeout 5s`, `COMMIT`).
- **A2. `pg_hba`** : lignes `hostssl farois_ftth +bureau_etudes <plages privées> ldap` (mêmes `ldapserver`/`ldapsuffix` que wyre), placées avec les lignes `ldap` wyre (services nommés toujours avant, §5.6) ; test : bind AD OK, rôles de service non capturés.
- **A3. Provisionnement** : création manuelle des rôles `CREATE ROLE <login> LOGIN IN ROLE bureau_etudes CONNECTION LIMIT …` (jamais de `PASSWORD`, garde-fous §5.2) ; test psql + bind AD par login ; relevé droits identique au partagé.
- **A4. Réconciliation** : extension `ldap_sync` (ou script dédié, au builder) — pour les rôles du groupe `bureau_etudes` : membre sorti du groupe AD BE → `NOLOGIN` + sessions coupées ; jamais de création ni de passage en `LOGIN` ; garde anti-mass-disable conservée. Nom du groupe AD BE à obtenir (point ouvert O1).
- **A5. Coupure (geste ops, jour de publication)** : `ALTER ROLE bureau_etudes NOLOGIN` + vérification (0 session partagée, nominatifs OK). Rollback : `LOGIN` (mot de passe partagé conservé hors dépôt pendant la transition).

### Volet B — plugin wyre nominatif

- **B1. Logique pure `bridge_nominatif.py`** : `resolve_pg_login()` (`lower(resolve_username())`, vide si hors regex serveur `^[a-z0-9._-]{1,63}$`) ; `is_auth_failure(exc)` (classe `28`) ; `upsert_root_crt_pem(existing, blocks)` ; `should_fallback(exc, has_shared_pw)` ; `nominal_authcfg_id(user, conn)`. Tests pytest sans QGIS.
- **B2. CA embarquées** : `farois-db-ca.crt` (Farois #1193) + `constructelbe-ca.pem` dans le paquet ; test PEM valides.
- **B3. Auth Manager** : `_store_password_encrypted(password, "wyre", username=login)` écrit `username=<login>` dans `9i19s56` (migration de la config partagée) ; `fixed_authcfg_id_for_user` étendu aux nominatifs.
- **B4. Dialogue** : login pré-rempli **modifiable** (fini `user='ftth_editor'` en dur) ; OK si login + mot de passe non vides.
- **B5. Sonde + repli** : avant toute couche, 1 connexion psycopg2 nominative `verify-full` ; classe `28` → 1 ressaisie → nouvel échec + `wyre.password` présent → repli (chemin 1.7.3 exact) + bandeau persistant + journal ; autre erreur → erreur actuelle sans repli. Mode mémorisé en settings, action « Réessayer mon accès nominatif », nouvelle sonde au démarrage suivant.
- **B6. TLS** : écriture `root.crt` à l'initialisation ; connexion QGIS `wyre` en `sslmode "5"` ; échec → bloquant.
- **B7. Couches + projets** : `_fix_layer_credentials` / `_strip_authcfg_from_dom` en nominatif : `user='<login>' authcfg=9i19s56`, jamais de `password=` en clair.
- **B8. Identité** : `_register_bridge_user` en nominatif → `SELECT` seul (ni INSERT ni UPDATE) ; `_clear_audit_identity()` au passage en nominatif ; repli = statu quo.
- **B9. Robustesse** : `credentials.json` tolérant (`wyre.password` absent → repli désactivé proprement, pas de `KeyError`) ; QML : auditer si les 38 `user='ftth_editor'` figés (10 fichiers) sont consommés au chargement, corriger si oui.
- **B10. i18n** : nouvelles clés FR/EN/PT (dialogue, bandeau, erreurs).

- **C2. Sonde be** : même sonde que wyre (1 tentative + 1 ressaisie, anti-verrouillage AD), pas de repli (coupure nette), erreur claire ; `verify-full` + `root.crt` commun.

### Volet D — scopes effectifs dans QGIS

- **D1. Lecture session** : après connexion nominative wyre, lire `(role, network_read, network_write, mro_ids, pop_ids)` via `current_gis_role()` + `ref.role_capabilities` / `ref.user_data_scopes` (SELECT permis — vérifié) ; fonction pure de mise en forme + tests.
- **D2. Lecture seule** : sans `network.write` → `setReadOnly(True)` sur les couches wyre.* éditables + message « accès lecture seule » ; avec `network.write` → couches éditables (le trigger serveur reste la barrière ; erreur 42501 traduite en message clair).
- **D3. Périmètre visible** : périmètre affiché dans le message de connexion (« périmètre : MRO … ») ; couches vides hors périmètre = normal et documenté (guide + message).
- **D4. Couches système** : vérification nominative `v_form_lists` (ValueRelation), `docs_elements`, styles DB, projets en base ; `v_duct_progress` scope-effective (invoker — vérifié).
- **D5. Recette scopes** : DESIGNER M1 (voit son périmètre, écrit dedans, refusé dehors avec message), VIEWER (lecture seule), ADMIN (tout) ; `qgis_projects` partagés par schéma documentés comme limite (pas de cloisonnement MRO, couches toujours filtrées).

## Risks / Open Questions

- **O1 (bloquant A4)** : nom du groupe AD des externes (source de vérité de la réconciliation) — à obtenir de l'IT/de Simon.
- **Rollback** : `plugins.xml` repointe 1.7.7 (zip conservé) ; serveur : rollback migration + `bureau_etudes LOGIN` + `FAROIS_DB_LDAP_ENABLED=false` si besoin (runbook).
- **Q2 (recette)** : libpq QGIS ≥ 3.28 accepte-t-elle une SAN IP en `verify-full` ? Sinon bascule DNS (spec §5.5).
- **Q3 (infra)** : la PKI interne chaîne-t-elle vers `constructelbe-ca.pem` ? Non bloquant pour 1.8.
- **Risque** : externe sans login au jour J (coupure nette) → gate strict (tous testés en bind AD avant publication, liste lot 0).
- **Limites documentées** : `qgis_projects` partagés par schéma (pas de cloisonnement MRO) ; `ref.v_form_lists` sans `security_invoker` (vérifié sans impact : pas de portée MRO/POP).
- Exclu : usage ou modification du code mTLS ; MFA/SSO Kerberos ; synchronisation de mots de passe AD→PG (techniquement impossible : l'AD ne fournit ni clair ni hash convertible — le SSO est assuré par le bind LDAPS direct).
